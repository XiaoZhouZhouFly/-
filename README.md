# 英文單字練習

手機優先的單字練習網頁，部署在 GitHub Pages。**資料和畫面分開**：單字在 `words.json`，練習進度在 `progress.json`，畫面在 `index.html`。

## 檔案（全部放在 repo 根目錄，不需要資料夾）

| 檔案 | 用途 | 誰會改 |
|---|---|---|
| `index.html` | 練習畫面與全部程式 | 只有明確要求改功能或介面時才動 |
| `words.json` | 單字本身 | 使用者、AI（批次新增、修改、刪除） |
| `progress.json` | 每個字的答對／答錯紀錄與「不熟」標記 | 由網頁匯出產生，通常不要手動改 |
| `README.md` | 本說明 | 規則有變時更新 |

## 部署

1. 把四個檔案放進 repo 根目錄。
2. Settings → Pages → Source 選 `Deploy from a branch`，Branch 選 `main`、資料夾選 `/ (root)`。
3. 之後開啟 `https://<帳號>.github.io/<repo 名稱>/`。

網頁用 `fetch` 讀取 JSON，所以**直接用檔案開啟（file://）會讀不到單字**，要用 Pages 網址或本機伺服器。

## words.json 格式

```json
{
  "version": 1,
  "words": [
    {"w": "ebb", "pos": "v.", "zh": "退潮、衰退、減弱", "src": "P1 #1"},
    {"w": "red herrings", "pos": "n.", "zh": "轉移注意力的事物、假線索", "src": "P7 #47"}
  ]
}
```

| 欄位 | 說明 |
|---|---|
| `w` | 英文單字或詞組。**必填**，不可重複（比對時不分大小寫、去頭尾空白）。一般用小寫，專有名詞才大寫。 |
| `pos` | 詞性，例如 `n.` `v.` `adj.` `adv.` `v./n.`。可為空字串。 |
| `zh` | 中文意思，多個意思用「、」分隔。**必填**。補充說明放在全形括號內。 |
| `src` | 出處，例如 `P2 #13`（第 2 頁第 13 題）。純備註，可為空字串。畫面會顯示在單字卡左上角。 |

### 給 AI：修改 words.json 的規則

- 每個單字**一行一個物件**，保持現有縮排，方便對照差異。
- 修改後必須是合法 JSON（無結尾逗號、使用 UTF-8、中文不要轉成 `\u` 編碼）。
- 新增時**追加到 `words` 陣列最後**，不要打亂既有順序（「原本順序」的出題模式依賴它）。
- 新增前先檢查是否已存在（不分大小寫）。重複的字不要新增，並告訴使用者哪些重複。
- 使用者貼來的清單格式可能是 `ebb (v.) 退潮、衰退`、`* 1. ebb (v.) 退潮`、`ebb | v. | 退潮` 等，統一轉成上面的物件格式。沒有出處就用空字串。
- 若單字是變化形（例如 teetering），原樣保留，不要自行改成原形，除非使用者要求。
- 使用者要求的中文意思若看起來有誤，先照做，再另外提醒。
- **刪除或改名一個單字時，也要同步處理 `progress.json`**（見下一節），否則會留下沒有對應單字的進度。
- 完成後回報：新增幾個、略過哪些重複、改了哪些、有無格式看不懂的行。

## progress.json 格式

為了節省空間，每個字只佔一行，欄位名稱只在 `fields` 寫一次：

```json
{
  "version": 2,
  "fields": ["bad","ok","streak","weak","t"],
  "words": {
    "ebb": [2,5,0,1,29913919],
    "surge": [0,3,2,0,29913920]
  }
}
```

- 鍵是**單字轉成小寫並去頭尾空白**後的結果（必須和 `words.json` 的 `w` 對得上）。
- 陣列依 `fields` 順序：

| 欄位 | 說明 |
|---|---|
| `bad` | 累計答錯次數 |
| `ok` | 累計答對次數（單字卡按「會了」也算） |
| `streak` | 目前連續答對次數，答錯歸零；連續答對 2 次會自動取消不熟（單字卡按「會了」則直接取消） |
| `weak` | `1` 是不熟、`0` 不是 |
| `t` | 最後更新時間，**Unix 分鐘**（毫秒時間戳除以 60000 取整數）。跨裝置合併時以較新的為準 |

### 給 AI：修改 progress.json 的規則

- 這個檔案通常由網頁「匯出」產生，**沒有明確要求不要手動改**。
- 刪除單字時，移除對應的鍵；改名時，把鍵改成新的小寫單字。
- 使用者要求「全部重置」時，把 `words` 改成 `{}`。
- 手動新增紀錄時，`t` 要填目前的 Unix 分鐘，否則可能被其他裝置較新的紀錄蓋掉。
- 頂層的 `updated`、`note` 欄位是給人看的，網頁不讀取，可保留。

## 網頁怎麼合併資料（給 AI 理解行為用）

- 開啟網頁時讀取 repo 的 `words.json` 與 `progress.json` 當作正式資料。
- 在某台裝置上新增的單字、答題產生的進度，先存在該瀏覽器的 localStorage，**不會自動寫回 GitHub**。
- 畫面右上角「匯出」按鈕上的數字，表示這台裝置有多少變更還沒上傳。
- 匯出的 `words.json` ＝ repo 的單字＋這台新增的；匯出的 `progress.json` ＝ repo 的進度＋這台較新的紀錄。上傳覆蓋舊檔後，重新整理即生效，已上傳的本機暫存會自動清掉。
- 若兩台裝置都改過進度，最後上傳的那份會覆蓋另一份；單字同理。要避免互相覆蓋，先在一台上傳並重新整理，再用另一台。

## 練習模式與出題順序

- 模式：單字卡、選擇題（英文選中文）、拼字（看中文與第一個字母，輸入英文）、單字表（搜尋、標記不熟、新增）。
- 篩選：「全部」或「不熟」。
- 出題順序（下拉選單，記在該裝置上）採**加權隨機**：符合條件的字更容易排前面，但每輪順序不同；「原本順序」除外。

| 選項 | 權重 |
|---|---|
| 隨機 | 全部 1 |
| 不熟優先 | 不熟 6、其他 1 |
| 答錯最多優先 | 1 ＋ 3 × `bad` |
| 正確率最低優先 | 有練過：0.3 ＋ 6 × (1 − `ok`/(`ok`+`bad`))；沒練過：0.1 |
| 沒練過優先 | 沒練過 10、其他 1 |
| 最久沒練優先 | 沒紀錄 10、其他 1 ＋ min(距今天數, 30) |
| 原本順序 | 照 `words.json` 順序，不隨機 |

權重寫在 `index.html` 的 `weightOf()`，要調整時改那個函式。

## 要求 AI 改單字時的範例說法

- 「把下面這批單字加進 words.json，出處都寫 `P8 #30`：……」
- 「把 `shambles` 的意思改成……」
- 「刪除 `tramps`，連進度一起清掉。」
- 「檢查 words.json 有沒有重複或格式錯誤。」
- 「把 progress.json 全部重置。」

## 維護提醒

- 改完 JSON 後，確認能被解析（例如 `python3 -m json.tool words.json`）。
- 改 `index.html` 時，注意 `key()` 函式（單字轉小寫、去空白）是進度對應的依據，改動會讓舊進度失效。
- `progress.json` 目前的版本是 `2`，改欄位順序或內容格式時要同步更新 `fields`，並保持網頁能讀舊格式。
